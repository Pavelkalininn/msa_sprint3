### <a name="_qmphm5d6rvi3"></a>**Решение**
Контейнерная диаграмма C2 в нотации C4 изображена в файле container.puml

При выборе технологии получения данных об истории заказов было принято решение использовать запросы взаимодействующим микросервисам с помощью технологии gRPC
для ускорения получения данных и агрегации их в композиционный ответ с помощью graphQL, для возможности получения всех необходимых данных
одним запросом с одного ендпоинта и возможности гибкой настройки полей ответа.

Таким образом мы можем учесть все функциональные и нефункциональные требования

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
Альтернативным вариантом решения задачи является чтение логов Event Sourcing


**Недостатки, ограничения, риски**

Заказов у пользователя может быть много, хранить историю заказов нужно годами
В таком исполнении хранилище событий будет занимать большой объем памяти, поиск по нему будет долгим, а данные перед отображением пользователю
всё-равно придется преобразовывать и аггрегировать что замедлит ответ системы и не будет соответсвтовать пунктам 4 и 5 нефункциональных требований
